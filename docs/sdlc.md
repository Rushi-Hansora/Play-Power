# Software Development Lifecycle (SDLC) & Agile Plan

## 1. Methodology
The project follows an Agile iterative lifecycle structured into distinct sprints, with clear definition of done (DoD) for each phase.

```
Sprint 0: Discovery & Architecture (Requirements, Pinned Versions, System Design)
   ↓
Sprint 1: Core Listing Page (Header, Hero Collage, Details, Reviews, Location, Sticky Card)
   ↓
Sprint 2: Photo Tour & Lightbox (Full-Screen Categorized Tour, Single-Photo Viewer, Keyboard Nav)
   ↓
Sprint 3: Visual QA & Micro-interactions (Fidelity Check vs Reference Screenshots, Animation Polish)
   ↓
Sprint 4: AI Travel Concierge Prototype (Intent Parser, Constraint Extractor, Ranking, Booking Handoff)
   ↓
Sprint 5: MERN Backend Foundation (Express 5, MongoDB, Layered Architecture, REST APIs, Security)
   ↓
Sprint 6: Testing & DevOps (Vitest Unit Tests, Playwright E2E, GitHub Actions CI/CD)
   ↓
Sprint 7: Final QA & Delivery (Smoke Testing, Build Verification, Zero-Plagiarism Check, Docs)
```

## 2. Definition of Done (DoD)
A sprint or feature is marked complete only when:
1. Visual fidelity matches reference specifications.
2. Component is accessible via keyboard and screen reader.
3. Relevant unit and E2E tests pass.
4. Production build runs without warnings or errors.
5. Documentation and ADR logs are updated.
